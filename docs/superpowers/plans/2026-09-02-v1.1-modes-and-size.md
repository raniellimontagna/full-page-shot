# v1.1 — Capture modes and output size Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Let the user capture either the full page or just the visible viewport, and make outputs far smaller by default (1× scale, PNG) with optional 2× and lossy download formats.

**Architecture:** Three new preferences flow from the options page through `chrome.storage.sync` into the service worker. Full-page capture is unchanged up to the offscreen `finishCapture`, which now rescales and encodes per preference. Viewport capture is a new short path: one `captureVisibleTab`, no content script, no scrolling, straight to the offscreen encoder and the existing sinks. Mode selection: options default, right-click menu on the action icon, and a second keyboard command.

**Spec:** `docs/superpowers/specs/2026-09-01-full-page-shot-design.md` (to be amended in Task 4).

## Global Constraints

- Everything in the v1 spec still binds: a failed capture never leaves the page altered; frames stream one at a time; MV3; no `debugger`; content script never under `content_scripts`.
- **Clipboard is always PNG.** `ClipboardItem` with `image/png` is the only widely-pasteable image type. Lossy formats apply to the download only.
- New permission allowed: `contextMenus` (no install warning). No others.
- Defaults: `captureMode: 'full'`, `scale: 1`, `downloadFormat: 'png'`, lossy quality fixed at `0.85` (no UI).
- The stitching arithmetic (`page-metrics`, `stitch-plan`) is NOT touched. Scaling happens once, on the finished canvas.
- TypeScript strict, `noUncheckedIndexedAccess`, no `any`. pnpm. Conventional Commits in English. Stage explicit paths only.
- All five gates must stay green: `pnpm exec oxlint src tests e2e`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e`.

### Task 1: Preferences and options page

**Files:** Modify `src/shared/prefs.ts`, `src/options/App.tsx`, `tests/shared/prefs.test.ts`, `tests/options/App.test.tsx`.

**Produces:**
```ts
type CaptureMode = 'full' | 'viewport'
type Scale = 1 | 2
type DownloadFormat = 'png' | 'jpeg' | 'webp'
interface Prefs { toClipboard: boolean; toDownload: boolean; captureMode: CaptureMode; scale: Scale; downloadFormat: DownloadFormat }
const DEFAULT_PREFS: Prefs  // full, 1, png, both sinks on
const LOSSY_QUALITY = 0.85
```
`loadPrefs` must merge stored values over `DEFAULT_PREFS` so users upgrading from 1.0.0 (who have only the two booleans stored) get the new defaults, and must coerce invalid stored values back to defaults. Options page gains three controls (radio groups or selects) with real `<label>` association; keep the `load`/`save` props seam and the `role="alert"` warning. Tests: defaults, upgrade-merge, invalid-value coercion, each control round-trips, alert still conditional. Red-then-green for each new test.

### Task 2: Offscreen encoding — scale and format

**Files:** Modify `src/shared/messages.ts`, `src/offscreen/index.ts`, `src/offscreen/stitcher.ts`; create `src/shared/formats.ts`; tests `tests/shared/formats.test.ts`.

**Produces:**
- `finishCapture` request carries `{ scale: Scale; downloadFormat: DownloadFormat; devicePixelRatio: number }` and returns `{ ok: true; clipboardDataUrl: string; downloadDataUrl: string }` — PNG for clipboard always; download encoded per format. When both would be identical (png), return the same string twice rather than encoding twice.
- New `beginViewportCapture` / reuse: a request `{ type: 'encodeSingleFrame'; dataUrl; scale; downloadFormat; devicePixelRatio }` that takes ONE captured frame and returns the same two data URLs — the viewport path uses it.
- `Stitcher.export({ scale, dpr, format, quality })`: if `scale === 1 && dpr > 1`, draw onto a second `OffscreenCanvas` of `width/dpr × height/dpr` with `imageSmoothingQuality: 'high'`, then `convertToBlob`. Never mutate the stitched canvas.
- `src/shared/formats.ts`: `mimeFor(format)`, `extensionFor(format)` (`png→.png`, `jpeg→.jpg`, `webp→.webp`), `isLossy(format)`. Pure, unit-tested.
- Keep `assertNever` exhaustiveness on the request union.

### Task 3: Viewport mode, context menu, second command

**Files:** Modify `src/background/index.ts`, `src/background/capture-loop.ts` (only if a shared helper is extracted), `src/background/sinks.ts`, `src/shared/prefs.ts` (filename), `src/manifest.config.ts`, `tests/manifest.test.ts`, `tests/background/*`.

**Behaviour:**
- `captureTab(tabId, windowId, mode)`. `mode` resolves from: explicit (menu/command) else `prefs.captureMode`.
- **Viewport path:** validate URL → single-flight guard → `captureVisibleTab(windowId, {format:'png'})` → `encodeSingleFrame` → sinks. No injection, no `measure`, no scroll, no `hideFixed`, no watchdog. Restoration is not needed because nothing is altered — say so in a comment.
- **Full path:** unchanged, but `finishCapture` now carries scale/format/dpr, and the two returned data URLs go to the two sinks respectively.
- `buildFilename(now, hostname, { mode, format })`: `<host>-<stamp>[-viewport].<ext>`.
- Manifest: add `contextMenus` permission; second command `capture-viewport` with `Ctrl+Shift+U` / `Command+Shift+U`; `_execute_action` stays as the default-mode trigger.
- On install/startup, create two context-menu items with `contexts: ['action']`; `chrome.contextMenus.onClicked` dispatches by id; `chrome.commands.onCommand` handles `capture-viewport`.
- Badge and single-flight behave identically for both modes.
- Tests: mode resolution (explicit beats pref), viewport path never calls `sendToContent`, filename suffix/extension, manifest asserts `contextMenus` and both commands. Red-then-green each.
