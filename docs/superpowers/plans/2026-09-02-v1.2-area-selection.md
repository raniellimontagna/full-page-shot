# v1.2 — Area selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** A third capture mode: the user drags a rectangle over the visible viewport and gets just that region — clipboard and/or download, at the chosen scale/format.

**Architecture:** The content script draws a selection overlay inside a shadow root, returns a CSS-pixel rect (or `null` on cancel), and removes the overlay before replying. The service worker then does one `captureVisibleTab` and asks the offscreen document to crop (in device pixels) before the existing scale/format export. Everything downstream — sinks, badge, single-flight, filename — is reused. No scrolling, no `hideFixed`, no new permissions.

**Spec:** `docs/superpowers/specs/2026-09-01-full-page-shot-design.md` (amended in Task 5).

## Global Constraints

- All v1/v1.1 rules bind: a failed or cancelled capture never leaves the page altered (overlay removed in `finally` AND covered by the content-script watchdog); frames stream one at a time; MV3; no `debugger`; no `content_scripts`; clipboard always PNG; stitching arithmetic untouched.
- No new manifest permission. New command `capture-selection`, `Ctrl+Shift+S` / `Command+Shift+S` (NOT Ctrl+Shift+I — that is Chrome's DevTools shortcut and browser bindings beat extension commands).
- **Cancel is not failure.** `Esc`, a click without drag, or a selection smaller than `MIN_SELECTION_PX = 4` in either dimension → the content script replies `{ ok: true, rect: null }`, the service worker delivers nothing and shows a neutral badge (`·` grey, 1.5 s), never ✕.
- The overlay must be gone from the DOM and painted-away (two `requestAnimationFrame`s, the scroll-driver technique) BEFORE the content script replies, so `captureVisibleTab` never sees it.
- Rect math: CSS px from the overlay → device px `round(v × dpr)`, clamped to the captured frame's real dimensions. One pure function, unit-tested.
- TypeScript strict, `noUncheckedIndexedAccess`, no `any`. pnpm. Conventional Commits in English. Stage explicit paths only. Gates: `pnpm exec oxlint src tests e2e`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:e2e`.

### Task 1: Types, preferences, options, filename

**Files:** Modify `src/shared/prefs.ts`, `src/shared/messages.ts`, `src/options/App.tsx`, their tests.

**Produces:**
- `CaptureMode = 'full' | 'viewport' | 'selection'`; coercion accepts the new value; options page gets a third radio "Selected area".
- `interface CssRect { x: number; y: number; width: number; height: number }` (CSS px, viewport-relative).
- `ContentRequest` gains `{ type: 'selectArea' }`; `ContentResponse` success gains optional `rect: CssRect | null`.
- `encodeSingleFrame` request gains optional `crop?: CssRect` (CSS px; the offscreen converts using the request's `devicePixelRatio`).
- `buildFilename` accepts mode `'selection'` → `-selection` suffix.
- `MIN_SELECTION_PX = 4` exported from prefs or a new `src/shared/selection.ts`.
Tests: coercion of `'selection'`, filename suffix, options radio round-trip, `assertNever` sites still compile (extend the compile-gate test if present).

### Task 2: Selection overlay (content script)

**Files:** Create `src/content/selection-overlay.ts`; modify `src/content/index.ts`; tests in `tests/content/selection-overlay.test.ts` (jsdom) and `tests/content/index.test.ts`.

**Produces:** `selectArea(doc: Document, opts?: { minPx?: number }): Promise<CssRect | null>` — mounts a host element with a shadow root at `z-index: 2147483647`, `position: fixed; inset: 0`, dimmed backdrop, crosshair cursor, a live rectangle with a size label; `pointerdown`→`pointermove`→`pointerup` produces the rect; `Escape` or a sub-minimum rect resolves `null`. **Always** removes the host (in `finally`) and resolves after two `requestAnimationFrame`s so the removal has painted. Idempotent: a second call while one is active cancels the first. Exports `removeSelectionOverlay(doc)` for the watchdog.
`src/content/index.ts`: handle `selectArea` — exempt from the `originalScrollY === null` guard (like `measure`), arm the watchdog while the overlay is up (an abandoned overlay self-removes), clear it on reply; `restorePage()` also calls `removeSelectionOverlay`. Tests with synthetic pointer events: drag → rect; reverse drag (bottom-right to top-left) → normalised rect; Esc → null; tiny drag → null; host removed in every case; watchdog removes an abandoned overlay.

### Task 3: Crop in the offscreen encoder

**Files:** Modify `src/offscreen/stitcher.ts`, `src/offscreen/index.ts`; create `src/shared/crop.ts`; tests `tests/shared/crop.test.ts`, extend `tests/offscreen/*`.

**Produces:** `planCrop(rect: CssRect, dpr: number, frame: { width: number; height: number }): DeviceRect` — `round(v × dpr)` per edge, clamped to the frame, never zero-sized (throws a clear error if the clamped rect is empty). `stitcherFromFrame(dataUrl, crop?)` draws only the cropped source rect onto a canvas of the crop's size; scale/format export then applies as today. `encodeSingleFrame` threads `crop`. Tests: rounding on all four edges at dpr 1.25/1.5/2, clamping at frame edges, empty-rect error, `export` still called once for png.

### Task 4: Service-worker wiring

**Files:** Modify `src/background/index.ts`, `src/background/viewport-capture.ts` (or a new `selection-capture.ts`), `src/background/sinks.ts` (neutral badge), `src/manifest.config.ts`, tests.

**Behaviour:** mode `'selection'` → validate URL → single-flight → inject content script → `selectArea` → on `rect: null` release and show the neutral badge → else `captureVisibleTab(windowId)` → `encodeSingleFrame({ crop })` → sinks. `isTabStillActive` before capture as in viewport mode. dpr from `PageMeasurements`-free probe as in viewport mode. Third context-menu item "Capture selected area"; third command; `MODE_BY_ID` extended. Tests via injected deps: cancel path delivers nothing and never calls `captureVisibleTab`; success path passes the rect through; menu/command/manifest assertions.
